# 심사 시연 대본 (Demo Runbook)

> 목표: **5분 안에** 골든패스 한 바퀴 — *회의 대화 → requirements·constraints → 목업 → 누락 체크 → 버전 선택 → export* — 를 end-to-end로 보이고, 세 가지 차별점(근거 추적성 · 커버리지 게이트 · 결정적 계약)을 각인시킨다.
> 한 문장 메시지: *"회의에서 오간 말이 어느 요구·제약으로, 어느 화면 요소로 갔는지 전부 되짚을 수 있고, 하류로 나가는 계약은 모델 없이 늘 똑같이 뽑힙니다."*

## 사전 준비 (시연 30초 전)

```bash
npm run dev:server      # :3000
npm run dev:dashboard   # :5173
```

- 브라우저 **http://localhost:5173** 열기 — 단일 콘솔(모드 분리 없음). 좌측 대화, 우측 산출물.
- `.env`에 LLM 자격 설정 확인(Bedrock 또는 Anthropic). 없으면 모델 단계가 멈춘다.
- 시연용 녹취는 `fixtures/seed-transcripts/`에 3개 도메인이 있다: **01 태스크 상세(생산성) · 02 주문 상세(커머스) · 03 진료 예약(헬스케어)**. 이번 대본은 **02 주문 상세**로 진행한다(누락 체크에서 보여줄 "명시적 제외"가 풍부하다).

---

## 파트 1 — 대화에서 요구·제약으로 (1분 30초)

1. `fixtures/seed-transcripts/02-order-detail.txt` 내용을 좌측 대화 패널에 붙여넣는다. "실제 회의 녹취입니다. 박민구(운영팀장)·박수만(CS리드)·변규백(개발자)·이종덕(PO)·박유도(디자이너)의 요구가 발언별로 흩어져 있죠. 발언자는 전부 실명으로 보이고, 각 발언에 `u-NNN` 식별자가 작게 붙습니다."
   - (선택) 회의 중 나온 한 줄을 **수동으로** 덧붙여 본다. 입력창 옆 **발언자 선택/입력**으로 실제 화자명(예: 박수만)을 붙이고 전송 — "수동 입력도 `사용자:`로 뭉개지지 않고 누가 한 말인지 그대로 남습니다. 최근 화자는 기억되고요." (rev3 R3)
2. **생성**을 실행한다. 상단 진행 표시가 **① 요구·제약 추출 → ② 목업 publish** 순으로 도는 것을 가리킨다. (생성 중 새로고침해도 진행 상태가 서버에서 복원되고, 대화는 서버와 로컬이 화해되어 어긋나지 않는 점을 짧게 언급해도 좋다.)
   - (선택) **"N개 생성"**(예: 2개)을 지정해 실행하면, 같은 요구·제약에서 목업 **변형 N개**가 만들어져 `v1-1 · v1-2`로 나란히 뜬다. "모델의 비결정성을 대안으로 활용합니다 — 하나만 뽑고 끝이 아니라 나란히 놓고 고릅니다." 파트 3에서 마음에 드는 변형을 고른다. (rev3 R2)
3. 완료되면 우측에 **requirements·constraints 문서**와 **목업 프리뷰**가 뜬다.

**👉 강조 포인트 ① — 근거 추적성**
요구·제약 문서의 각 항목에 붙은 **`[근거: u-NNN]`** 태그를 짚는다.
"이 요구는 상상이 아니라 몇 번째 발언에서 나왔는지가 다 적혀 있습니다. 근거 없는 건 만들지 않아요." (원칙 2 / C-3)
- **constraints 쪽**도 함께 보인다: "PG 연동은 이번 스프린트 밖", "엑셀 내보내기는 범위 밖" 같은 **'하지 않는 것'** 도 요구와 동급으로 추출돼 근거가 붙어 있다.

---

## 파트 2 — 누락 체크와 휴먼 게이트 (1분 30초)

1. **누락 체크(coverage)** 를 실행한다. 대화 전체 대비 현재 요구·제약을 대조해, "요청됐으나 아직 반영 안 된 항목"이 체크리스트로 뜬다.
2. 후보 하나를 **채택** → 요구/제약으로 편입되고 근거 태그가 자동으로 따라붙는 것을 보인다.
3. 다른 후보(예: 엑셀 내보내기)를 **의도적 제외** → "이 제외 결정 자체가 하나의 constraint가 됩니다" 하며 constraints 문서에 `[근거: u-NNN]`과 함께 새 제약이 생기는 것을 보인다.

**👉 강조 포인트 ② — 커버리지 게이트 (요청은 휘발되지 않는다)**
"회의에서 나온 요청은 채택되거나 명시적으로 제외되거나, 둘 중 하나로만 끝납니다. 아무 반영처 없이 사라지는 요청이 없어요 — 오해가 개발까지 새어나가기 전에 회의 자리에서 잡습니다." (원칙 4 / C-5)

> (선택) 피드백 이터레이션: 대화에 새 발언을 한 줄 추가하고 다시 생성 → 근거 델타 기반으로 요구·제약이 고도화되고 목업이 republish되는 것을 짧게 보인다. "근거 없는 수정은 발생하지 않습니다." (원칙 3 / C-4)

---

## 파트 3 — 버전 선택과 export (1분 30초)

1. 버전 목록에서 만족한 버전을 고른다 → 그 버전의 requirements·constraints·목업이 함께 전환되는 것을 보인다. 변형이 여럿이면 `v{group}-{variant}`(예: `v1-2`)로 형제 중 하나를 고른다(변형이 하나면 `v{group}`). "따로 freeze하는 단계는 없습니다. **버전을 골라 Export하는 것 자체가 확정**입니다."
   - **버전 되감기(revert)** 시연: v3 결과가 마음에 안 들면, 왼쪽 대화 패널의 **`── v2 근거 경계 ──` 를 클릭**해 v2로 되감는다. "그 버전 이후는 전부 지워지고, 대화도 그 시점 스냅샷까지 되돌아갑니다. 되돌린 뒤 다음 입력으로 v3를 새로 만들 수 있어요 — 버전 관리를 사용자가 직접 손으로 합니다." 되감기 대상에 **export 이력이 있는 버전이 있으면 경고**가 뜨고, 재확인해야 진행된다. (rev3 R1)
2. **export** 실행 → `data/exports/<project>/<meeting>/v<n>/` 아래 세트가 생긴다: `requirements.md` · `constraints.md` · `mockup.html` · `visual-contract.json` · `visual-contract.yaml` · `trace.json` · `manifest.json` (7파일).
3. `visual-contract.json`(기계 판독)과 함께 사람이 읽기 쉬운 `visual-contract.yaml`을 열어 보인다.

**👉 강조 포인트 ③ — 결정적 계약**
"이 계약은 LLM이 지어낸 게 아니라, 목업 HTML의 좌표·역할·데이터 바인딩을 **기계(Playwright)가 읽어** 만든 겁니다. **같은 목업이면 언제 뽑아도 똑같은 계약**이 나오고, 이 단계 모델 비용은 0입니다." (원칙 5 / C-1)
- 실증: export를 한 번 더 실행해 동일한 `visual-contract.json`이 나옴을 보인다.
- 의의: "하류의 다른 개발 사이클·AI 세션은 HTML 전문을 매번 읽을 필요 없이, 이 저비용·오독 없는 계약만 받으면 SRS·HLD·LLD를 이어서 씁니다."

## 파트 4 — 마무리 (30초)

- 한 줄 정리: **대화 → 요구·제약(근거태그) → 목업 → 누락 체크(채택/제외) → 버전 선택 → export(확정본+목업+결정적 계약 JSON·YAML+추적 메타)**.
- 왕복 한마디: "이 export를 다른 회의체에서 **다시 import**하면 중요 의결사항과 근거가 그대로 복원돼 논의를 이어갑니다."
- 못: *"우리는 AI-DLC로, AI-DLC의 앞단을 만들었습니다."*

## 백업 플랜 (라이브 실패 시)

- 모델 지연/오류로 잡이 멈추면: 이미 만들어 둔 최신 버전을 열어 목업·요구·제약을 띄우고, 근거 사슬은 구두로 설명.
- 그래도 막히면 `data/exports/`의 기존 export 세트(특히 `visual-contract.json` + `trace.json`)를 열어 결정적 계약과 근거 추적을 파일로 직접 보인다.
- 스크린샷 백업은 `screenshots/`에 있다.
