# U3 콘텐츠·문서 rev2 — Functional Design

> 담당: U3(콘텐츠·문서). 대상 파일은 `fixtures/**` · `README.md` · `docs/**`만. src·dashboard 미수정.
> 근거: `requirements/improvements-rev2.md` G(#8) · D(#4) · E(#5), 부수적으로 A(#1,#7)·H(#9).

## 무엇을 왜 바꾸나

콘텐츠·문서는 **코드가 아니라 사용자·심사자가 처음 마주치는 표면**이다. rev2에서 엔진 흐름이
바뀌었으므로(freeze 폐기, export 세트 확장, 실명 표시), 문서·시드가 옛 흐름을 설명하면
데모가 코드와 어긋난다. 아래 세 가지 정합을 맞춘다.

### 1. G — 발언자 실명 (근거: improvements-rev2 §G / #8)
- **현재**: 시드 녹취·예시 목업의 발언자가 역할명(기획자·개발자·운영팀장…) + 익명 예시 이름(김지원·박도현).
- **바꾸는 것**: 시드 녹취 3종 + 레거시 단일 시드의 발언자를 확정 캐스트 5인
  **이종덕 · 변규백 · 박유도 · 박민구 · 박수만**으로. 형식은 `이름(역할):`(rev2 G의 "역할+실명"
  허용안) — 실명이 앞·주체, 역할은 괄호로 문맥 보존(데모 내레이션이 역할을 계속 참조하므로).
- **왜**: rev2 G는 "예시 데이터를 실명으로" 명시. 회의 녹취라는 제품 서사에 익명 역할표보다
  실제 이름이 현실감을 준다. `u-NNN` 안정 식별자는 서버 파서가 라인 단위로 부여하므로
  발언자 라벨을 실명으로 바꿔도 추적성 불변(표시 스코프만 변경, 내부 식별자 무영향).
- **불변**: 각 녹취의 **명시적 제외 발언**(첨부파일·엑셀·PG·문자알림 등)과 **누락 후보로 남길
  발언**은 텍스트 그대로 유지 — 발언자 라벨만 교체. 커버리지 데모가 의존하는 내용을 건드리지 않음.

**캐스트 배정**(재직 팀 1개가 회의마다 재등장하는 설정):
| 이름 | 상시 성격 | 01 태스크 | 02 주문 | 03 진료 |
|---|---|---|---|---|
| 이종덕 | 기획/PO 리드 | 기획자 | PO | 기획자 |
| 변규백 | 개발 | 개발자 | 개발자 | 개발자 |
| 박유도 | 디자인 | 디자이너 | 디자이너 | 디자이너 |
| 박민구 | 도메인 오너 | PO | 운영팀장 | 원무과장(+범위선언) |
| 박수만 | 현장 리드 | — | CS리드 | 간호팀장 |

- 02는 5인 전원 등장. 03은 원문 6역할(원무과장·기획자·개발자·간호팀장·디자이너·PO) 중
  PO 2줄(로그인·결제 범위 제외)을 도메인 오너 **박민구(원무과장)**의 범위 선언으로 흡수 →
  5인 유지. 내용(제외 결정)은 그대로.

### 2. D — Freeze 제거 · Export 통합 (근거: improvements-rev2 §D / #4)
- **현재 문서**: README 골든패스·export 세트·사용 매뉴얼, demo-runbook 파트3·마무리가 모두
  `freeze(major 고정) → export` 2단계를 설명. "major" 개념·`v<major>` 경로 사용.
- **바꾸는 것**: freeze 개념·버튼 서술 제거. **버전 선택 → Export = 확정** 단일 흐름으로 서술.
  export 산출 경로를 `v<major>` → **`v<n>`(버전 단위)**로. "major" 표현 폐기.
- **왜**: rev2 D 결정은 freeze 폐기. 문서가 freeze를 계속 설명하면 UI(버튼 없음)와 모순.

### 3. E — YAML 출력 (근거: improvements-rev2 §E / #5)
- **바꾸는 것**: export 세트 문서 표를 **6→7파일**로. `visual-contract.yaml`을 `.json`과
  동일 내용(사람·기계 판독)으로 추가 명시.
- **왜**: rev2 E 결정 — 세트에 yaml 병기. 문서 표가 실제 산출과 일치해야 데모에서 열어 보일 수 있음.

### 부수 반영 (문서로만; 코드는 U1/U2 담당)
- **A(#1,#7) 진행상태 복원**: 사용 매뉴얼·runbook에 "생성 중 새로고침해도 진행상태가 복원된다"
  한 줄 반영(옛 "클라 메모리에만" 뉘앙스 정리).
- **H(#9) 버전 삭제**: 사용 매뉴얼에 "버전 목록 우클릭 삭제, export 이력 있으면 경고 후 재확인"
  한 줄 반영.

## 담당 밖(건드리지 않음)
- src·dashboard 코드, 데이터모델(`frozen`/`major` 필드 제거 등), `/freeze` 엔드포인트 → U1/U2.
- `requirements/**` 정본 개정 → 재-inception 담당.
- git/npm 실행.

## 실행법 정합
README·runbook의 실행 명령은 실제 `package.json` scripts(`dev:server`·`dev:dashboard`·
`build:dashboard`·`start`)와 이미 일치 — rev2 편집 중에도 그대로 유지, 변경하지 않음.
