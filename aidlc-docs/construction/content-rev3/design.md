# U-content3 rev3 — Functional Design

> 담당: 문서(U-content3). 대상 파일은 `docs/**` · `aidlc-docs/construction/content-rev3/**`만.
> README.md는 팀원(동시 작업) 담당 — 건드리지 않음. fixtures·src·dashboard 미수정.
> 근거: `requirements/improvements-rev3.md` R1(버전 revert) · R2(다중 변형) · R3(발언자·동기화).

## 무엇을 왜 바꾸나

rev3에서 콘솔에 세 가지 조작이 들어온다: (R1) 대화 패널의 버전 근거 경계선을 눌러 그
버전으로 되감기, (R2) 한 번에 변형 N개를 만들어 `v{g}-{k}`로 골라 잇기, (R3) 수동 입력에
실제 화자명을 붙이고 서버 동기화를 견고화. **시연 대본이 이 조작을 보여주지 않으면 심사자는
rev3의 사용자-주도 버전 관리를 놓친다.** `docs/demo-runbook.md`만 이 세 흐름을 반영한다.
(README는 별도 담당이므로 여기서 제외.)

### 1. R1 — 버전 revert (경계 클릭 되감기) (근거: improvements-rev3 §R1)
- **반영 위치**: 파트 3(버전 선택). 기존 "버전 목록에서 고른다" 옆에 되감기 흐름 추가.
- **대본에 넣는 것**: 왼쪽 대화 패널의 `── vN 근거 경계 ──` 클릭 = 그 버전으로 되감기.
  "v3가 마음에 안 들면 v2 경계를 눌러 되돌리고, 다음 입력으로 v3를 새로 만든다"는 사용자-주도
  서사. 되감기 = **선택 버전 이후 전부 삭제 + transcript를 그 버전 스냅샷까지 되감음 + draft
  복원**. export 이력이 있는 버전이 삭제 대상이면 **경고 → 재확인(force)** 한 줄 명시(rev2 H 일관).
- **왜**: 버전 관리가 UI 조작으로 승격됐으므로 데모가 그걸 손으로 보여야 차별점이 산다.

### 2. R2 — 다중 변형 생성 v{g}-{k} (근거: improvements-rev3 §R2)
- **반영 위치**: 파트 1(생성) 또는 파트 3 — 생성 시 "N개 생성"을 시연하고 파트 3에서 형제 중 선택.
- **대본에 넣는 것**: "N개 생성" 요청 → 같은 요구·제약에서 목업 변형 N개(LLM 비결정성=변형) →
  `v1-1 · v1-2`로 나열, 마음에 드는 변형 선택 후 이어감. 표시 라벨 규칙(변형>1이면 `v{g}-{k}`,
  아니면 `v{g}`) 한 줄. 편집(델타)은 선택된 변형 기준.
- **왜**: "하나만 뽑고 끝"이 아니라 대안을 나란히 놓고 고르는 흐름이 디자인 협업 서사를 강화.

### 3. R3 — 발언자 필드 · 동기화 개선 (근거: improvements-rev3 §R3)
- **반영 위치**: 파트 1(대화 입력) 및 선택 피드백 이터레이션 각주.
- **대본에 넣는 것**: 수동으로 한 줄 추가할 때 **입력 옆 발언자 선택/입력**으로 실제 화자명을
  붙인다(최근 화자 유지). "누가 한 말인지가 수동 입력에도 보존된다." 전송은 **await PUT**으로
  서버 반영을 보장하고, 로드 시 서버·로컬을 **reconcile**하므로 새로고침/다중 입력에도 대화가
  어긋나지 않는다 — 한 줄로 견고성 언급(기존 "새로고침해도 진행 복원" 각주와 결합).
- **왜**: rev2까지 수동 입력이 `사용자:`로 뭉개졌다. 발언별 근거 추적(강조 ①)이 제품 핵심인데
  화자 소실은 그 서사를 깬다. 데모가 실명 부착을 손으로 보여야 추적성 주장이 일관된다.

## 실행법 정합
runbook 사전 준비의 실행 명령(`dev:server`·`dev:dashboard`)은 실제 scripts와 이미 일치 —
rev3 편집 중에도 변경하지 않는다. 계약(엔드포인트) 서술은 UI 조작 관점으로만 넣고 스키마는
jd 정본을 참조.
