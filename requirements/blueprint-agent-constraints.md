# Blueprint Agent 구현 예외사항

## 제외 기능 (구현하지 않음)

### 1. 인증 및 계정 관리
- 사용자 회원가입 및 로그인
- 조직/팀 단위 멀티테넌시
- 역할 기반 권한 관리 (열람 전용 / 편집 / 승인자 구분)
- 외부 계정 연동 로그인 (OAuth, SNS)
- 다단계 인증

### 2. 화면 편집 및 디자인 도구
- 드래그 앤 드롭 방식의 시각 편집기
- 픽셀 단위 원본 재현 (하이브리드 충실도 원칙상 명시적으로 포기)
- 디자인 시스템 편집 및 관리 도구
- 컴포넌트 라이브러리 구축
- 반응형 브레이크포인트별 화면 생성 (기준 뷰포트 1종만)
- 다크 모드 등 테마 변형

### 3. 코드 생성 범위
- 실행 가능한 완전한 애플리케이션 스캐폴딩
- 빌드 · 배포 · CI 파이프라인 생성
- 테스트 코드 자동 생성
- 데이터베이스 마이그레이션 스크립트 생성
- 생성된 코드의 자동 실행 및 동작 검증
- 기존 코드베이스에 대한 패치 적용

### 4. 레거시 흡수 범위
- 로그인이 필요한 페이지의 인증 자동화
- 단일 페이지 애플리케이션의 동적 라우팅 완전 대응
- 자바스크립트로만 도달 가능한 화면 상태의 탐색
- 네비게이션 그래프의 시각화 (데이터로만 보관)
- 흡수된 앱 구조의 편집 UI (페이지 선택 UI가 실용적 필요를 대체)
- 언어 모델을 이용한 데이터 객체 이름 정규화 (병합은 결정적 규칙으로만)
- 로봇 배제 규칙을 우회하는 크롤링

### 5. 협업 기능
- 다중 사용자 동시 편집
- 산출물에 대한 코멘트 및 리뷰 스레드
- 승인 워크플로 및 결재
- 알림 (푸시, 이메일, 메신저)
- 변경 이력 알림 및 구독

### 6. 데이터 및 운영
- 관계형 데이터베이스 영속화 (파일 기반 산출물 저장으로 대체)
- 백업 및 복구
- 산출물 보존 기간 정책 및 자동 삭제
- 사용량 기반 과금 및 쿼터 관리
- 감사 로그 조회 UI (메타데이터 영속화까지만)
- 다중 인스턴스 수평 확장

### 7. 외부 연동
- 이슈 트래커 연동 (Jira, Linear 등)
- 디자인 도구 임포트/익스포트 (Figma 등)
- 문서 도구 연동 (Confluence, Notion 등)
- 메신저 연동 (Slack, Teams 등)
- 형상 관리 연동 (생성 코드의 자동 커밋/PR 생성)
- 회의 플랫폼 연동 (Zoom, Meet 등의 녹취 자동 수집)

### 8. 모델 및 인프라
- 모델 파인튜닝
- 자체 모델 서빙 인프라
- 다중 모델 라우팅 및 폴백 정책 UI
- 프롬프트 편집 UI (프롬프트는 시스템 내부 자산으로 고정)
- 응답 캐싱 계층

### 9. 추적성 심화 (로드맵 — 현 범위 밖)
- 회의 타임스탬프 도입 (발언별 실제 발화 시각)
- 발언 식별자와 화면 요소 간 직접 링크
- 발언 식별자와 요구사항 항목 간 자동 매핑
- 요구사항과 코드 간 양방향 링크
- 버전 이력 화면에서의 근거 발언 뷰어 (메타데이터 영속화까지만)
- 산출물 간 차이 비교(diff) 뷰

### 10. 다국어 및 접근성
- 콘솔 UI의 다국어 지원 (한국어 단일)
- 생성 산출물의 다국어 변형
- 화면 접근성 자동 검사 및 교정

### 11. 설계 문서 확장 및 버전 계보 (로드맵 — 현 범위 밖)

명세 역도출(§3.4)의 산출물은 **요구사항 명세 · 데이터 모델 · API 명세 3종**으로 한정한다.
아래는 과거에 요구되어 설계까지 이루어졌으나 명시적으로 범위 밖으로 내린 항목이다
(근거: `blueprint-agent-origin-requirements.md` o-015 / o-016 / o-017).

**문서 확장 — 하지 않음**
- 설계 문서 세분화: 상위 수준 설계(HLD) · 하위 수준 설계(LLD) · 아키텍처 결정 기록(ADR) 분리 산출
- 통신 계약 문서: 데이터베이스 구조 명세, 데이터베이스↔백엔드 API 명세, 프론트엔드↔백엔드 API 명세의 개별 산출
- 추적성 리포트의 문서 형태 산출 (메타데이터 영속화까지만 — §9와 동일 기준)
- 산출 문서의 이용자 단계별 분리 (이해관계자 모드는 상위 설계까지, 개발자 모드는 상세까지)

**버전 계보 — 하지 않음**
- 과거 임의 버전에서의 분기(fork) 생성 — 버전 계승은 최신 버전 단일 계열만 지원
- 확정(freeze)의 불변 잠금 및 재확정 차단
- 버전 계보 그래프 시각화
- 확정 산출물의 버전 귀속 (현행: 확정 시점마다 독립된 실행 단위로 보존)

> 이 항목들을 구현 대상으로 되돌릴 경우, 요구사항 정의서 §3.3.1(확정)과 §3.4.1(명세 도출),
> §3.2.3(버전 이력 관리)을 함께 개정해야 한다. 세 절이 서로 맞물려 있어 하나만 바꾸면 모순이 생긴다.

## 설계 제약 (반드시 지켜야 할 것)

아래는 "하지 않는 것"이 아니라, **다르게 만들면 안 되는 것**이다. 요구사항 정의서 §1.4에 대응한다.

### C-1. 확정·계약 추출 단계에 언어 모델을 도입하지 않는다
화면을 계약으로 변환하는 단계는 결정적이어야 한다. 이 단계에 모델을 넣어 "더 똑똑하게" 만드는 설계는 시스템의 존재 이유(저비용·재현성)를 무효화한다. 동일 입력은 언제나 동일 출력을 낳아야 하며, 이 단계의 모델 호출 비용은 0이다.

### C-2. 명세 역도출 단계에 원본 화면 마크업을 입력으로 넣지 않는다
역도출의 입력은 시각 계약 문서로 한정한다. "계약에 정보가 부족하면 원본도 같이 보여주자"는 해결책은 금지한다. 정보가 부족하면 **계약 스키마를 확장**해서 해결한다. 유일한 예외는 비용 절감 측정의 대조군 실행이다.

### C-3. 근거 없는 보완 생성을 허용하지 않는다
요구 브리프는 발언에 없는 내용을 추가하지 않고, 화면은 브리프에 없는 요소를 추가하지 않는다. "사용자 경험을 위해 취소 버튼도 넣어주자" 같은 선의의 보완이 추적 사슬을 끊는다. 부족한 것은 채우지 말고 부족한 채로 두어, 다음 회의에서 발언으로 들어오게 한다.

### C-4. 수정은 델타 발언 없이 발생할 수 없다
화면 수정 모드의 입력은 직전 버전과 근거 브리프로 구조적으로 한정한다. 근거 없이 수정이 가능한 경로를 만들지 않는다.

### C-5. 레거시 원본은 단 한 번만 접촉한다
흡수 단계 내부의 정규화 지점에서만 원본을 소비하고, 이후 모든 처리는 정규화된 화면 모델을 사용한다. 후속 단계가 원본을 다시 읽는 경로를 만들지 않는다.

### C-6. 비용 절감률을 품질 측정 없이 보고하지 않는다
절감률은 언제나 품질 동등성 검증 결과와 함께 제시한다. 절감만 단독으로 제시하는 것은 측정이 아니라 홍보다.
