## A. 실행 상태 가시성·복원 (#1, #7)
- **현재**: 목업 생성 중 진행 표시가 약해 사용자가 놓침. 생성 중 새로고침하면 "생성중" 상태가 유실(클라 메모리에만 존재).
- **목표**:
  - 생성 중 **명확한 진행 표시** — 오버레이/스피너 + 실행 버튼 비활성 + 현재 단계 강조.
  - 진행 중 작업(job) 상태를 **서버에 영속**(회의체에 연결) → 로드/새로고침 시 재조회·복원하여 "현재 작업중인지" 표시.
- **수용 기준**: 생성 중 새로고침 → "생성중"이 그대로 복원되고, 완료 시 결과가 반영된다.

## B. 버전 ↔ requirements·constraints 동기화 (#2)
- **현재**: 버전 칩 클릭 시 **목업만** 전환, requirements·constraints는 최신(draft)에 고정.
- **목표**: 버전 선택 시 **그 버전의 requirements·constraints·목업이 함께 전환**. (버전은 이미 {req,con,mockup} 묶음으로 저장되어 있으므로 UI가 선택 버전 값을 로드.)
- **수용 기준**: v1 선택 시 v1의 req/con/목업, v2 선택 시 v2의 것이 일관되게 보인다.

## C. 근거 경계 시각화 (#3)
- **목표**: 채팅 타임라인에 각 버전이 **대화의 어디까지를 근거로 삼았는지** 가로 구분선으로 표시(예: 발언들 사이 `──── v2 근거 경계 ────`).
- **근거**: 버전별 `transcriptSnapshot`/`groundingIds` 경계를 채팅에 마킹(추적성 §3.8 시각화).

## D. Freeze 제거 · Export 통합 (#4) — 결정: **freeze 없앰**
- **현재**: freeze·export·version 클릭 기능이 중복.
- **목표**: **freeze 버튼·개념 제거.** 버전 목록에서 **버전 선택 → Export = 확정** 단일 흐름.
- **Cascade (모델/코드 영향)**:
  - 데이터모델의 `frozen`/`major` 필드·`/freeze` 엔드포인트·`versionByMajor` 제거.
  - export는 **버전 단위**로 산출(`data/exports/<project>/<meeting>/v<n>/`). "major" 개념 폐기.
  - 콘솔: Freeze 버튼 제거, 버전 목록 클릭 → 선택 버전 Export.
- **수용 기준**: freeze 버튼이 없고, 임의 버전을 골라 Export하면 그 버전의 세트가 나온다.

## E. YAML 출력 추가 (#5) — 결정: **visual-contract.yaml**
- **목표**: export 세트에 **`visual-contract.yaml`** 추가 — 시각 계약을 JSON과 **YAML 양쪽**으로 산출(기계·사람 판독 편의). 결정적 추출 결과를 `yaml.stringify`로 함께 기록.
- **수용 기준**: export 디렉토리에 `visual-contract.json`과 `visual-contract.yaml`이 동일 내용으로 존재.

## F. 새 회의체 폼 닫기 (#6)
- **현재**: "새 회의체" 폼을 열면 취소/닫기 버튼이 없음.
- **목표**: 폼에 **취소/접힘(토글) 버튼** 추가.

## G. 발언자 실명·현실감 (#8) — 결정: **이름 크게 + u-NNN 작게 병기**
- **표시**: 채팅 버블·근거 태그에서 **발언자 실명을 크게**, 식별번호 **`u-NNN`은 작게 옆에 병기**(예: **이종덕** `u-003`).
- **내부**: `u-NNN`은 §3.1.2 결정적 안정 식별자로 **그대로 유지**(추적성 불변). 표시만 실명 중심.
- **예시 데이터**: 시드 녹취·예시 목업의 발언자를 **실명**으로 — 이종덕 · 변규백 · 박유도 · 박민구 · 박수만.
- **수용 기준**: 화면에서 발언자 이름이 크게 보이고 u-NNN이 작게 병기되며, 예시 녹취가 위 실명을 사용한다.

## H. 버전 삭제 + 방어 로직 (#9) — 결정: **export 이력 기준 방어**
- **목표**: 버전 목록에서 **우클릭 → 삭제**. (원치 않게 생성된 v2/v3 정리용.)
- **방어**: 해당 버전에 **export 이력이 있으면 경고**를 띄우고, 사용자가 **"그래도 삭제"** 재확인한 경우에만 삭제. (freeze 개념이 없어졌으므로, 보존 방어선은 export 이력을 기준으로 한다.)
- **Cascade**: 삭제 시 최신 버전 포인터·버전 계보 재계산. export 세트 파일 처리(경고 문구에 명시).
- **수용 기준**: export 안 한 버전은 즉시 삭제, export한 버전은 경고+재확인 후 삭제된다.
