# Blueprint Agent 구현 예외사항 (v2 — 단일 고객 모드)

> v2 재검토: 산출물을 목업 HTML · requirements.md · constraints.md 3종으로 한정. 아래 §0에 v2에서 새로 내린 항목을 모은다.

## 0. v2에서 범위 밖으로 내린 항목 (재검토 결과)

- **코드 생성 전체** — 프론트/백/DB 대표 코드 산출 기능 제거(§3.5 삭제). 명세→코드 실증은 이번 범위 아님.
- **SRS · ERD · OpenAPI 개별 산출 제거** — 요구는 단일 `requirements.md`로 통합(FR-NN 번호 유지). 데이터 모델·API 명세를 별도 문서로 내지 않는다.
- **개발자 모드 · 모드 토글 제거** — 콘솔은 단일 고객 모드 하나. 개발자용 6뷰(contract·code·spec·versions 탭 구성)를 없앤다.
- **시각 계약(contract)의 사용자 노출 제거** — freeze/계약은 **내부 엔진**으로만 존재(문서를 결정적으로 근거짓기 위함). 사용자에게 계약 원문을 별도 뷰로 보여주지 않는다.
- **요구 브리프의 산출물 노출 제거** — 브리프는 목업 생성용 내부 중간 산출물. 최종 요구는 requirements.md.

> 위 항목을 되돌릴 경우 요구사항 정의서 §2.2·§3.4·§3.6을 함께 개정한다.

## 1. 제외 기능 (구현하지 않음)

### 1.1 인증 및 계정 관리
- 회원가입/로그인, 멀티테넌시, 역할 기반 권한, 외부 계정 연동, 다단계 인증.

### 1.2 화면 편집 및 디자인 도구
- 드래그 앤 드롭 시각 편집기, 픽셀 정합 재현(기준 뷰포트 1종 근사만), 디자인 시스템 편집, 컴포넌트 라이브러리, 반응형 브레이크포인트별 생성, 다크모드 등 테마 변형.

### 1.3 문서 산출 범위 (v2)
- requirements.md·constraints.md 외 문서(SRS/ERD/OpenAPI/ADR/HLD/LLD 등) 개별 산출.
- 생성 문서의 이용자 단계별 분리(개발자 모드가 없으므로 무의미).
- 추적성 리포트의 문서 형태 산출(메타데이터 영속화까지만).

### 1.4 코드 생성
- 실행 가능한 애플리케이션·대표 코드 스캐폴딩, 빌드/배포/CI 생성, 테스트 코드 자동 생성, DB 마이그레이션 생성, 생성물 자동 실행·검증, 기존 코드 패치.

### 1.5 레거시 흡수 전체 — 구현 안 함
- 단일/사이트 흡수, 크롤 제어, 흡수 후 경로 일체. 향후 별도 요구로 복원.

### 1.6 협업 기능
- 다중 사용자 동시 편집, 코멘트/리뷰 스레드, 승인 워크플로, 알림, 변경 구독.

### 1.7 데이터 및 운영
- 관계형 DB 영속화(파일 기반으로 대체), 백업/복구, 보존기간 정책, 과금/쿼터, 감사 로그 조회 UI(메타 영속화까지만), 수평 확장.

### 1.8 외부 연동
- 이슈 트래커, 디자인 도구 임포트/익스포트, 문서 도구, 메신저, 형상관리 자동 커밋/PR, 회의 플랫폼 녹취 자동 수집.

### 1.9 모델 및 인프라
- 파인튜닝, 자체 서빙 인프라, 다중 모델 라우팅 UI, 프롬프트 편집 UI(프롬프트는 내부 고정 자산), 응답 캐싱 계층.

### 1.10 다국어 및 접근성
- 콘솔 UI 다국어(한국어 단일), 생성물 다국어 변형, 접근성 자동 검사·교정.

### 1.11 버전 계보
- 과거 임의 버전 분기(fork) — 버전 계승은 최신 단일 계열만. 확정 불변 잠금·재확정 차단, 계보 그래프 시각화 미구현.

## 2. 설계 제약 (반드시 지켜야 할 것)

"하지 않는 것"이 아니라 "다르게 만들면 안 되는 것". 요구사항 정의서 §1.4에 대응.

### C-1. 확정·계약 추출 단계에 언어 모델을 도입하지 않는다
계약은 내부 엔진이지만 여전히 **결정적**이어야 한다. 동일 입력은 동일 출력, 이 단계 모델 호출 비용은 0. 이 결정성이 requirements.md의 재현성을 보증하는 근거다.

### C-2. 문서 도출 단계에 원본 화면 마크업을 입력으로 넣지 않는다
requirements.md 도출의 화면-측 입력은 **시각 계약**으로 한정한다(회의 발언은 허용). "계약에 정보가 부족하면 원본 HTML도 같이 보여주자"는 금지. 부족하면 계약 스키마를 확장해 해결한다.

### C-3. 근거 없는 생성을 허용하지 않는다 (v2 강화)
- requirements.md는 발언·계약에 없는 요구를 추가하지 않는다.
- **constraints.md는 발언에 명시된 제외/비목표만 담거나, 사용자가 명시적으로 확정한 항목만 담는다.** AI가 흔한 제약을 임의로 지어내지 않는다. 근거 없으면 비워 둔다.
- 화면은 브리프에 없는 요소를 추가하지 않는다.

### C-4. 목업 수정은 델타 발언 없이 발생할 수 없다
수정 모드 입력은 직전 버전 + 델타 발언에서 도출된 수정 브리프로 구조적으로 한정한다. 델타가 없으면 수정 자체가 일어나지 않는다.
